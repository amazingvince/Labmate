The winning version

Keep the submission narrow and verifiable. Ship one deterministic golden path rather than a broad product.

Core narrative
Labmate lets a data scientist give Claude a business prediction problem, dataset, target, metric, and rubric. Claude profiles the data, catches leakage, proposes experiment cards, waits for human approval, runs sandboxed experiments, critiques its own results, reruns a corrected experiment, and produces a reproducible model card. The live app shows the full evidence ledger.

What to emphasize

The impressive part is not that Claude trains a model. The impressive part is that Claude knows when not to trust its own result, rejects it, reruns it correctly, and leaves behind a reproducible evidence trail.

Framing warning: do not call this a dashboard. The rules prohibit projects where a dashboard is the main feature. Call the UI a mission-control cockpit for an autonomous scientific loop. The product is the agent-native evidence ledger.

3. Implement the runner

Metrics + guardrails 
Implement the Labmate experiment runner.

Focus file:
- apps/modal-runner/runner.py

Required model families:
- dummy
- logistic_regression
- random_forest
- hist_gradient_boosting

Required behavior:
- deterministic split
- fixed seed
- respect banned/leaky columns
- threshold tuned on validation only
- final test evaluated once
- reject any manifest that says tune_on: "test"
- return clear status, metrics, params, artifacts, rationale, dataset_hash, code_hash, seed, and executor

Required metrics:
- recall_at_fpr
- precision
- roc_auc
- pr_auc
- false_positive_rate

Golden demo:
Create one intentionally flawed manifest that tunes on the test split, make the critic reject it, then rerun with validation thresholding.

Do not add XGBoost, LightGBM, uploads, auth, or advanced search unless the golden path already works.

5. Make the workflow executable

Golden path 
Make .claude/workflows/run-study.js execute the full Labmate golden path.

Required sequence:
1. read examples/sla_tickets/brief.md
2. create study
3. profile dataset
4. write data contract and leakage exclusions
5. propose 5–8 experiment cards
6. request approval
7. record approval
8. record this human feedback:
   "Recall matters more than precision, but false positives above 20% are not acceptable."
9. ensure that feedback affects at least one later manifest
10. launch baseline plus at least 5 model experiments
11. create or trigger a critique that catches leakage or test-set tuning
12. rerun the corrected experiment
13. select best model
14. write final report/model card
15. grade the study against docs/rubric.json

Output:
- Print the study id.
- Print the live study URL.
- Print the grader verdict.
- Write or append SESSION_LOG.md with the brief, human steering, agent actions, self-correction moment, and verification commands.

Reliability requirement:
This can be deterministic and tailored to examples/sla_tickets. Do not over-generalize.

Project title:
Labmate — an agent-native data science harness

One-sentence pitch:
Labmate gives Claude a safe, repeatable harness for autonomous data science: it profiles a dataset, proposes hypothesis-driven experiments, runs them in sandboxes, critiques its own methodology, records human feedback, and produces a reproducible model card.

Problem:
Data scientists spend too much time on experiment mechanics: profiling data, checking leakage, writing training scripts, logging runs, documenting rationale, and turning business feedback into modeling constraints. AutoML optimizes after the problem is framed; Labmate helps frame, run, critique, and document the scientific loop.

What we built:
We built a working Labmate study on a synthetic support-ticket SLA dataset. Claude creates a study, profiles the dataset, catches leakage fields, proposes experiment cards, waits for human approval, runs sandboxed experiments, records metrics and rationales in an evidence ledger, catches a test-set-tuning issue, reruns the corrected experiment, and writes a final model card. A grader verifies completion against a machine-readable rubric.

Why it matters:
This is the missing orchestration layer for agentic data science. It turns Claude from a coding assistant into a controlled scientific collaborator whose assumptions, actions, corrections, and evidence are logged and verifiable.
